# Token Strategy Documentation

This directory outlines how the system tracks and manages token usage across all components.

## Token Accounting
- **Input Tokens** – tokens from the user query and any retrieved context.
- **Output Tokens** – tokens generated by the LLM answer.
- **Embedding Tokens** – tokens consumed when generating embeddings for documents.
- **Total Tokens** – sum of the above for a single request.
- **Prompt Tokens** – tokens used in the LLM prompt (including retrieved chunks and system instructions).

## Limits & Budgets
- **Per‑request input limit:** 4,000 tokens.
- **Per‑request output limit:** 1,000 tokens.
- **Embedding batch limit:** 2,000 tokens per document chunk.
- **CRAG retry budget:** Additional 500 tokens allocated for a second retrieval‑grade‑rewrite cycle.

## Strategies
- **Chunk size** – 500‑token chunks to stay within limits.
- **Truncation** – truncate longer documents with a summarizer before embedding.
- **Duplicate handling** – de‑duplicate overlapping chunks to avoid token waste.
- **Cost tracking** – approximate cost calculation (free‑tier pricing) for monitoring.

## Monitoring
- Export token counters to Prometheus (via OpenTelemetry).
- Alert when daily token usage approaches free‑tier quota.
